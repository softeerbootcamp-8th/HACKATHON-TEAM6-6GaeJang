# 기능 구현 파이프라인 (3일 해커톤용)

이슈 트래커도 없고 팀 컨벤션 문서도 아직 두텁지 않은 상태에서, 기능 하나를
"계약 확정 → 구현 → 테스트"까지 한 사이클로 빠르게 끝내기 위한 스킬이다.

설계 문서를 따로 쓰지 않는다. 대신 코드를 쓰기 전에 애매한 것만 짧게 사람에게 묻는다.

## 단계 1 — 범위 판정

요청 내용을 보고 스스로 범위를 정한다.

| 요청에 나오는 것 | 범위 | 수행 단계 |
|---|---|---|
| 엔티티·상태 규칙만 (API 없음) | `domain` | 3 → 5(단위) → 6 |
| 엔드포인트·요청/응답·서비스 로직 | `backend` | 3 → 5 → 6 |
| 화면 + API 둘 다 | `fullstack` | 3 → 4 → 5 → 6 |
| 화면만, 이미 있는 API 소비 | `frontend` | 4 → 5 → 6 |

애매하면 좁게 잡는다. 요청에 없는 화면·엔드포인트를 상상해서 만들지 않는다.

## 단계 2 — 계약 확정 게이트 (사람에게 묻는 유일한 지점)

코드를 쓰기 전에 **계약 초안**을 짧게 제시한다. 문서 파일 만들지 말고 대화에 바로 쓴다:

```
[정지 이벤트 알림]
POST /api/ridings/{ridingId}/stop-events → 201, ApiResponse<StopEventResponse>
  요청: riderId, lat, lng
  상태: 같은 교차로 구간에서 첫 정지 감지 시 이벤트 생성 → 접근 중인 라이더에게 SSE 브로드캐스트
  예외: 이미 해당 구간에 활성 이벤트 있으면 중복 생성 안 함 (409 대신 idempotent하게 무시)
프론트: RidingMap 컴포넌트에서 SSE 구독, 알림 토스트 표시
```

그다음 **정말 갈리는 지점만** 질문한다. 한 번에 최대 3개, 여기서 끝낸다. 선택지마다 트레이드오프 한 줄씩.

물어볼 가치가 있는 것:
- 동시성 문제 생길 수 있는 부분 (여러 라이더가 동시에 위치 갱신/이벤트 트리거)
- 상태 전이가 두 가지 이상으로 설계될 수 있을 때
- 에러 응답 정책이 선례 없을 때
- 새 라이브러리 추가할 때

물어보지 말 것: 관례가 이미 있는 것(네이밍, 응답 포맷, 폴더 위치), 되돌리기 쉬운 것.
**질문할 게 없으면 묻지 말고 진행한다.**

받은 답변은 메모해두고, 단계 6 커밋 메시지/PR 설명에 반영한다.

## 단계 3 — 백엔드 구현

`references/backend.md`를 읽고 그 규칙대로 계층을 만든다.
Repository → Service → DTO → Controller 순. Lombok으로 보일러플레이트 최소화.
JPA 기본 사용, 복잡한 조회는 JPQL, 성능 필요한 곳만 native query.

## 단계 4 — 프론트 API 연동

범위가 `fullstack` 또는 `frontend`일 때만 수행한다. `references/frontend.md`를 읽는다.
백엔드 로컬 프로파일로 띄우고 → `pnpm generate:api` (Orval) → 라우트 옆 `-components/`에 화면 구현.
`src/api/generated/`는 손으로 고치지 않는다.

## 단계 5 — 테스트

정상 흐름만 쓰면 의미 없다. 동시성·중복 요청처럼 **이 기능에 실제로 일어날 수 있는 것**을 골라 테스트.

- 단위 테스트 — 도메인 규칙, 상태 전이. 항상 쓴다.
- 통합 테스트 — 서비스 + JPA + 트랜잭션 경계에서 동시성/정합성 걸리는 부분만.
- E2E — 범위가 `fullstack`일 때, 대표 시나리오 하나만.

테스트는 반드시 실행하고 결과를 그대로 보고한다. 실행 안 한 테스트를 통과했다고 쓰지 않는다.

```bash
cd backend && ./gradlew test
cd frontend && pnpm typecheck
```

## 단계 6 — 커밋

```
<type>: <한글 설명>
```
`feat`/`fix`/`test`/`docs`/`refactor` 중 하나. 기능과 무관한 포맷팅 섞지 않는다.
마지막에 보고할 것: 만든 엔드포인트/화면, 테스트 결과, 계약에서 **일부러 뺀 것**.

## 이 스킬에서 하지 않는 것

- 요청에 없는 기능을 "있으면 좋을 것 같아서" 덧붙이기
- 정합성 중요한 코드(위치 갱신, 이벤트 중복 감지)를 테스트 없이 넘기기
- CI/CD, 모니터링, 배포 설정 건드리기 — 이건 프로젝트 초기 세팅 영역이라 이 스킬 범위 밖 (한 번만 세팅하고 GEMINI.md/CLAUDE.md에 고정)
- `src/api/generated/`, `routeTree.gen.ts` 손으로 수정
